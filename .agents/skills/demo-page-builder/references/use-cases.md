# 业务说明（用例）撰写细则

当用户需要为页面/功能编写**业务说明（用例）**（触发词：业务说明、用例、登录用例、评论用例、写用例、正常流程、异常流程），或在交付文档中需要补齐用例描述时，按本文档撰写完整、可开发/测试/验收的用例。

> 依据：2bPM（自学成AI产品经理）第 3.17 章「业务说明（用例）」的用例描述法。原文示例见 `docs/业务说明-用例.md` 与本文件末尾的「完整示例」。

## 触发场景

- 用户要求为登录、评论、下单、支付等任一业务功能编写用例
- 用户给出功能列表/正常流程+异常流程清单，要求补全成完整用例
- 需要在 PRD / 交接文档中追加「业务说明（用例）」章节

## 用例结构（每个用例必须包含）

1. **用例概述**：用例名称、用例编号、参与者、优先级、前置条件、后置条件、触发事件
2. **正常流程**：按步骤列出「从进入/触发到完成」的完整操作链路
3. **异常流程**：表格化列出每条异常（编号 / 触发操作 / 系统表现 / 处理结果）
4. **业务规则**：字段规则、校验规则、错误提示、边界约束、防重复/防刷等

### 用例概述字段说明

| 字段 | 说明 |
|---|---|
| 用例名称 | 一句话描述（如「用户登录」「发表评论」） |
| 用例编号 | 统一前缀（如 `UC-LOGIN-01`），按模块分组 |
| 参与者 | 谁来执行（游客 / 已登录用户 / 管理员等） |
| 优先级 | P0/P1/P2，P0 为核心功能 |
| 前置条件 | 用例开始前必须满足的状态 |
| 后置条件 | 用例成功结束后系统达到的状态 |
| 触发事件 | 用户或系统触发本用例的动作 |

## 写作规则

- **正常流程**：分步编号，按用户真实操作顺序（聚焦 → 输入 → 校验 → 提交 → 结果），每步动作+系统反馈
- **异常流程**：穷举输入校验、格式校验、长度限制、网络异常、重复提交、权限不足等场景；每条给明确的系统表现（按钮禁用/提示文案/行为）与处理结果（停留在原页/保留输入/重试）
- **业务规则**：把可测试的硬性规则单独成表（字段名/类型/是否必填/校验规则/默认值/错误提示/备注），敏感词脱敏、防重复发布、防暴力破解等策略一并列出
- **涉及产品决策但未确认的**（如失败锁定策略、排序方向）：如实标注「需产品确认」，不擅自假定
- 用例编号统一、可回溯，异常流程编号与正常流程区分（如 A1–A9 / B1–B7）

## 完整示例

### 登录用例（UC-LOGIN-01）

**正常流程**

1. 用户点击页面「登录」入口，登录框弹出
2. 输入手机号：焦点进入手机号输入框，弹出数字键盘（无法输入字母）
3. 输入密码：密码以密文显示，可切换明文/密文
4. 点击「登录」，系统校验手机号与密码
5. 校验通过：登录框关闭，回到登录前所在页面
6. 系统获取登录状态与用户信息并展示（头像、昵称）

**异常流程**

| 编号 | 触发操作 | 系统表现 | 处理结果 |
|---|---|---|---|
| A1 | 未输入手机号 | 「登录」按钮置灰不可用 | 无法提交 |
| A2 | 未输入密码 | 「登录」按钮置灰不可用 | 无法提交 |
| A3 | 手机号非 11 位 | 「登录」按钮置灰不可用 | 无法提交 |
| A4 | 手机号框获取焦点 | 弹出数字键盘，无法输入字母 | 只能输入数字 |
| A5 | 手机号已满 11 位 | 无法继续输入第 12 位 | 长度受限 |
| A6 | 手机号未注册 | 点击登录，提示「账号未注册」 | 停留登录框，可重输 |
| A7 | 手机号正确、密码错误 | 点击登录，提示「密码错误」 | 停留登录框，可重输 |
| A8 | 手机号密码正确但网络异常 | 点击登录，提示「网络异常，请稍后再试」 | 停留登录框，可重试 |
| A9 | 忘记密码，输入不存在的手机号 | 点击发送验证码，提示「手机号未注册」 | 无法发送验证码 |

### 评论用例（UC-COMMENT-01）

**正常流程**

1. 用户点击评论框，评论框获取焦点
2. 输入框弹出，可输入评论内容
3. 输入评论内容（15–140 字）
4. 点击「发布」，系统校验并提交
5. 发布成功：输入框关闭，页面刷新/局部更新，评论列表出现新评论（内容、发布者、时间）

**异常流程**

| 编号 | 触发操作 | 系统表现 | 处理结果 |
|---|---|---|---|
| B1 | 未输入内容 | 「发布」按钮置灰不可用 | 无法提交 |
| B2 | 内容不足 15 字 | 「发布」按钮置灰不可用 | 无法提交 |
| B3 | 内容超过 140 字 | 无法继续输入（或提示已达上限） | 长度受限 |
| B4 | 发布时失去网络 | 提示「网络异常，请稍后再试」 | 发布失败，内容保留 |
| B5 | 网络延迟重复点击发布 | 提示「同一用户不能重复发布相同内容评论」 | 去重，不产生重复评论 |
| B6 | 内容含敏感词 | 敏感词以 `*` 替代后正常发布 | 发布脱敏后的文本 |
| B7 | 未登录点击发布 | 提示「请先登录」并引导跳转登录 | 无法发布，跳转登录 |

**业务规则**

- 字数规则：最少 15 字，最多 140 字；未达下限发布禁用，超上限无法继续输入
- 敏感词规则：命中敏感词库的词用 `*` 逐字替代，替代后内容仍可发布
- 重复发布规则：同一用户不得短时间内重复发布完全相同内容；命中拒绝并提示
- 网络异常：发布失败不清空已输入内容，可重试

## 交付衔接

- 编写用例的页面若为 demo 页，示例数据仍按 `mock.md` 走 Umi mock；用例描述的校验/交互逻辑要真实实现
- 用户确认页面满意后，交接文档（`handover.md`）的「功能说明」一节与本文的「业务规则」保持一致
