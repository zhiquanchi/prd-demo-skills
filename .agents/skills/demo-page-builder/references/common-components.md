# 公共组件规则（demo-page-builder 的参考文档）

> 本文件是 `demo-page-builder` skill 的 additional material，不是独立 skill。新增/修改页面遇到跨页面复用的布局组件（侧边栏、导航、页头页脚等）时，由 demo-page-builder 的流程引导到这里执行。

## 规则一：侧边栏是公共组件（硬性要求）

页面左侧侧边栏（对应渲染页面 DOM 中的 `/html/body/div[1]/div/div[1]`，即全局布局的侧边导航区块）**必须作为公共组件处理**：

- **提取为共享组件**：侧边栏实现放在 `src/components/`（如 `src/components/Sidebar/index.tsx`），由布局或各页面统一引用；**禁止在每个页面里复制粘贴一份侧边栏代码**，发现重复副本时合并回公共组件
- **不要改动侧边栏样式**：侧边栏的配色、宽度、字体、间距、选中态等视觉样式**保持项目现状，一律不改**。新增页面、调整页面内容时，侧边栏原样复用，不做任何"顺手美化"
- **使用项目中原有的样式**：侧边栏的样式来源只有一处——项目里已有的那份实现（antd Menu / ProLayout menu + 项目已有的 antd-style 样式）。不写第二份样式、不从参考稿/其他页面重新推导配色，不做覆盖（override）
- 侧边栏的菜单项绑定与选中态规则仍按 `references/routes.md` 执行——允许的只是**新增菜单项、绑定跳转**这类结构性变更，视觉样式不变

## 规则一·补充：禁止重复侧边栏

新增/复刻页面时，必须先检查项目是否已通过 `src/layouts/`、ProLayout、antd `Layout.Sider` 或公共 `Sidebar` 渲染全局侧边栏和顶部导航。

若全局布局已存在侧边栏：

1. 新增/复刻页面时禁止在 `src/pages/**` 或页面私有组件中再次渲染侧边栏、站点导航、项目导航或同职责的顶部栏。
2. 原稿中的侧边栏只作为内容结构参考，不直接复刻；页面仅实现全局布局 `Content` 区域内的业务工作台。
3. 原稿的导航入口、选中态和路由跳转必须映射到项目现有公共侧边栏；确有缺失时，只允许向公共侧边栏新增菜单项，不得新建第二套侧边栏。
4. 实现前必须输出布局归属表：`全局布局负责的区块`、`页面负责的区块`、`原稿中需省略或映射的区块`。
5. 验证时必须检查页面 DOM：同一视口只能存在一个主侧边栏。若原稿和项目侧边栏同时出现，视为失败，必须移除页面内重复侧边栏。

## 规则二：其他跨页面组件同样处理

凡是出现在多个页面的布局区块（侧边栏、顶部导航、页头、页脚、全局背景等）：

1. **先查项目里是否已有**：已有公共实现就引用它，不重写；没有才在 `src/components/` 新建，并让后续页面复用同一份
2. **样式以项目现状为准**：公共组件的样式只在项目内唯一来源处定义，页面不得各自覆盖；用户明确要求改样式时，也只改公共组件那一处，让全部页面一致生效
3. **复刻场景也不例外**：按 `references/replicate.md` 复刻新页面时，原稿中的侧边栏/导航若项目已有公共实现，优先复用项目现有的公共组件及其样式，不按原稿重画一份

## 验证

- 改完任一页面上：侧边栏外观与改动前一致（宽度、配色、选中态无变化），且项目里侧边栏实现只有一份（搜 `src/pages/` 下无重复的侧边栏代码）
- 新增菜单项时：样式与既有菜单项完全一致，仅多一个可点击项，点击能跳转（验证方法见 `references/routes.md`）
