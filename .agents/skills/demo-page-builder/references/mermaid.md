# Mermaid 生成细则

> 依据：第三方 `mermaid-skill`（https://github.com/WH-2099/mermaid-skill，`.claude/skills/mermaid`）。生成 Mermaid 图时按本文档流程与语法书写，保证代码能直接渲染。
>
> 本 skill 内生成 Mermaid 的场景：交接文档（`handover.md`）的**用户操作流程图**、以及「设计与用户体验」一节的**用户流程（User Flow）**——每个功能一条，流程数量与功能数量一致，条数多时每条独立成图（编号命名如 `用户流程-检索`）。两者都用 `flowchart`，主用本文「流程图（flowchart）」一节即可；如需其他图型按「图型选择」选型并查对应语法。

## 生成流程

1. **理解需求**：分析需求/页面行为，确定最合适的图型（是流程图、时序图、状态图还是别的）
2. **查语法**：按图型查阅对应语法参考（本文已收录 flowchart 核心语法；其他图型查 mermaid 官方文档 `https://mermaid.js.org/syntax/`）
3. **生成代码**：按语法规范书写 Mermaid 代码
4. **应用样式**：需要时用主题/`style`/`classDef` 增强可读性

## 图型选择

| 图型 | 适用场景 |
| --- | --- |
| `flowchart`（流程图） | 流程、决策、步骤——**本 skill 交接文档的流程图/用户流程主用此型** |
| `sequenceDiagram`（时序图） | 交互、消息、API 调用 |
| `classDiagram`（类图） | 类结构、继承、关联 |
| `stateDiagram`（状态图） | 状态机、状态迁移 |
| `entityRelationshipDiagram`（ER 图） | 数据库设计、实体关系 |
| `gantt`（甘特图） | 项目计划、时间线 |
| `mindmap`（思维导图） | 层级结构、知识图谱 |
| `timeline`（时间线） | 历史事件、里程碑 |
| `requirementDiagram`（需求图） | 需求追踪 |
| `c4`（C4 图） | 系统架构（C4 模型） |

## 输出规范

生成的 Mermaid 代码必须：

1. 包在 ```` ```mermaid ```` 代码块里
2. 语法正确、能直接渲染（**不能**写错节点/连线语法）
3. 结构清晰：节点/连线一行一条、正确换行缩进
4. 节点用语义化命名（如 `A`/`B`/`Start`/`End`，或业务语义名）
5. 需要时加样式提升视觉效果

## 流程图（flowchart）语法

### 基本结构

```
flowchart <方向>
    节点 --> 节点
```

方向取值：
- `TB` / `TD`：从上到下（最常用，交接文档流程图用 TD）
- `BT`：从下到上
- `LR`：从左到右
- `RL`：从右到左

### 节点形状

| 形状 | 语法 | 语义 |
| --- | --- | --- |
| 矩形（默认/过程） | `A[文本]` | 普通步骤 |
| 圆角矩形（事件） | `A(文本)` | 事件/开始结束 |
| 菱形（决策） | `A{文本}` | 判断分支 |
| 圆柱（数据库） | `A[(文本)]` | 数据存储 |
| 六边形（准备） | `A{{文本}}` | 条件准备 |
| 体育场形（终止点） | `A([文本])` | 开始/结束 |

> 新旧两种写法均可：`A[文本]` 传统写法，`A@{ shape: rect, label: "文本" }` 新写法（v11.3+，形状名见下表简写）。交接文档流程图用传统写法即可。

常用新形状简写（`A@{ shape: <名>, label: "..." }`）：`rect`（过程）、`rounded`（事件）、`diam`/`decision`（决策）、`stadium`/`terminal`（终止）、`cyl`/`database`（数据库）、`circle`/`start`（开始）、`dbl-circ`/`stop`（结束）、`hex`/`prepare`（准备）。

### 连线（边）

| 类型 | 语法 |
| --- | --- |
| 箭头 | `A --> B` |
| 无箭头（开放） | `A --- B` |
| 带文字箭头 | `A -->|文字| B` 或 `A-- 文字 -->B` |
| 带文字无箭头 | `A---|文字|B` 或 `A-- 文字 ---B` |
| 虚线箭头 | `A -.-> B` |
| 虚线箭头带文字 | `A-. 文字 .->B` |
| 粗线箭头 | `A ==> B` |
| 双向箭头 | `A <--> B` |

### 子图（subgraph）

```
flowchart TD
    subgraph 分组名
        A --> B
    end
    B --> C
```

### 样式（style / classDef）

```
flowchart TD
    A[开始] --> B{判断}
    style A fill:#f9f,stroke:#333,stroke-width:2px
    classDef 高亮 fill:#bbf,stroke:#f66,stroke-width:2px
    class B 高亮
```

### 注释

用 `%%` 开头，独占一行，会被解析器忽略：

```
flowchart TD
%% 这是一个注释
    A --> B
```

### 常见坑

- 节点文本里的 `end` 会破坏语法：**用大写或首字母大写（`End`/`END`）**，或用引号包起来
- 文本含特殊字符（括号等）时用双引号包住：`A["文本(特殊)"]`
- 连线/节点的 `o`、`x` 作首字母时前面加空格或大写，避免被识别成特殊箭头

## 交接文档使用建议

- **用户操作流程图**：用 `flowchart TD`，从「进入页面」开始，把使用者每一步操作、每个分支决策点、最终目标串起来，让演示者照着就能讲、就能试
- **用户流程（User Flow）**：**每个功能一条**，与本页「四、功能说明」的用例一一对应；主流程 Happy Path 用文字或 `flowchart TD` 描述「开始 → 步骤 → 决策点 → 结束」，并列关键分支与异常/退出路径；功能增改后同步增补/更新对应流程
- 决策点用菱形 `{}`，步骤用矩形 `[]`，文字写在箭头 `-->|文字|` 上表达分支原因
- 参考 `references/handover.example.md` 的用户操作流程图示例
