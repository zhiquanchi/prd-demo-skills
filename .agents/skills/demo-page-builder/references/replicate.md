# 参考原型复刻（用户提供了 demo / 原型时）

当用户提供了参考物——HTML 文件或代码片段、页面截图、设计稿、线上页面 URL 等——目标是**用当前技术栈（Umi Max + `assets/project-template/package.json` 白名单组件库）一比一复刻**。复刻覆盖两个维度，缺一不可：**功能**（所有交互与逻辑必须完整复刻、真实可用）和**布局**（结构、配色、文案与原稿一致）。本文档规定复刻流程；组件白名单、git 提交、服务验证、**示例数据用 Umi mock** 等通用规则仍以 `SKILL.md` 及其 `references/mock.md` 为准。

## 第一步：理解原稿（先分析，不写代码）

复刻的前提是看懂原稿。先把参考物拆解成一份**复刻清单**，再动手写代码：

- **HTML / 代码片段**：直接读代码，提取：
  - DOM 结构与区块划分（header / 侧栏 / 卡片列表 / 表单区等）
  - 布局方式与尺寸（flex / grid / 定位、宽度、列数、对齐）
  - 精确配色（背景、文字、边框、主色——**记录具体色值**，不要凭感觉）
  - 字体、字号、字重、行高、间距、圆角、阴影
  - **功能与交互逻辑（重点，逐项记录）**：每个可点/可操作的元素分别做什么——tab 切换、展开收起、弹窗/抽屉的打开与关闭、表单填写与校验、按钮触发的动作、搜索/筛选/排序、分页、增删改、状态变化等；有代码时直接读事件处理和状态逻辑，把每个交互的触发条件与结果写清楚
  - 文案（逐字记录）
- **截图 / 设计稿**：逐区域识别区块结构、组件类型和大致配色；看不清的细节如实标注为"推测"，复刻后请用户确认
- **URL**：先抓取页面内容再按 HTML 流程分析

分析完先向用户输出复刻清单（区块划分 + 关键样式参数 + 组件映射），用户确认或无疑义后再进入实现。原稿信息不足（如只有局部截图、缺少交互说明）时，先问清楚再动手，不擅自脑补大范围设计。

## 第二步：组件映射（原稿元素 → 白名单组件）

复刻不等于抄原稿代码——原稿里的组件必须映射到清单内的库：

| 原稿里的 | 复刻用 |
|---|---|
| 通用 UI（按钮/表单/表格/导航/卡片/弹窗） | antd / @ant-design/pro-components |
| AI 对话类组件 | @ant-design/x |
| 图标 | @ant-design/icons（找视觉上最接近的） |
| 图表（chart.js、D3、ECharts 等任何来源） | echarts + echarts-for-react |
| 自定义装饰元素、特殊样式区块 | antd 基础组件 + antd-style 自绘 |

清单内没有对应能力时，按 `SKILL.md` 的拒绝流程告知用户并给替代方案，**禁止为了"还原度"引入原稿用的第三方库**（包括手写复制外部组件源码）。

## 第三步：一比一复刻（功能 + 布局）

### 功能复刻（最高优先级，必须完整）

原稿里的每一个功能都要真实实现、真实可用，**禁止做成"点了没反应"的摆设**：

- 复刻清单里记录的每个交互逐一实现：tab 能切换、弹窗能开关、表单能填写校验提交、搜索/筛选/排序/分页真实生效、列表能增删改——全部真实可用，**示例数据用 Umi mock（见 `references/mock.md`）驱动**
- 交互的**结果**也要复刻：原稿点了之后出现什么（新面板、提示、数据变化、跳转），复刻版就要出现什么
- 示例数据放 `mock/`、页面用 `request` 取数即可，但逻辑必须完整——mock 的是数据来源，不是功能本身（细则见 `references/mock.md`）

### 布局复刻

还原优先级从高到低：

1. **布局结构**：区块划分、排列方式、栅格/列数与原稿一致
2. **配色**：用原稿提取的**精确色值**（通过 antd-style / cssinjs 或 ConfigProvider theme token 写入），不要默认套 antd 主题色——原稿配色与 antd 默认冲突时以原稿为准
3. **文案**：与原稿逐字一致（除非用户要求替换）
4. **字体/字号/间距/圆角/阴影**：按复刻清单的参数实现
5. **细节交互表现**：hover 效果、过渡动画等用 antd 组件自带交互或简单 state 实现

其他要求：

- 样式用 `antd-style`（或 antd v5 token 体系），不写白名单外的 CSS 方案
- 示例数据放 `mock/`（Umi mock，见 `references/mock.md`），不接真实后端；原稿里的真实文案/数据可直接作为 mock 返回值
- 原稿中的图片素材：本地有可用的就用；没有用占位图（色块/渐变）代替并告知用户

## 第四步：对比验证

1. 按 `references/dev-server.md` 起服务，确认页面打进 bundle 可访问
2. **功能核对（先做）**：对照复刻清单逐项实际操作——每个按钮都点一遍、每个 tab 都切一遍、每个表单都试一遍，确认所有功能真实可用、结果与原稿一致，缺一个补一个
3. 有条件截图时，将复刻页面截图与原稿并排对比，**逐项核对复刻清单**（布局、配色、文案、间距），有偏差就改
4. 把地址发给用户，请用户对照原稿确认功能与还原度；不像就改到像为止
